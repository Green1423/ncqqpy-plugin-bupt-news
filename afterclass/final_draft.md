# 北邮“第二课堂”微信小程序行为分析报告

**报告日期：** 2026 年 11 月 4 日  
**分析对象：** 北邮“第二课堂”微信小程序反编译产物  
**分析方式：** 静态源码分析、行为建模、完全离线模拟与自动化回归  
**证据边界：** 未连接生产服务器，未使用真实账号、凭据或用户数据

## 一、执行摘要

本报告对北邮“第二课堂”微信小程序的页面、状态、接口、设备能力及关键业务流程进行系统梳理，并将静态分析结果转化为可执行的本地行为模型。该小程序采用 uni-app 技术体系，业务覆盖活动、签到、通知、积分商城、成绩单和后台管理，具有较完整的客户端状态管理与微信设备能力调用。

本次分析共识别 **20 个注册页面、40 个业务 REST 接口、3 个辅助接口和 60 类主要行为动作**。在隔离环境中，模拟器完成了 **75 项全场景检查，全部通过；另有 21 个自动化测试全部通过**。页面、接口和动作目录的可执行模型覆盖率均为 100%，真实网络请求为 0。

需要强调的是，上述覆盖率表示“静态目录中的行为均有对应模拟实现”，不代表真实服务端响应、微信原生渲染或第三方 H5 内部逻辑已经得到验证。生产行为仍需在合法授权的测试环境和真机中复核。

## 二、分析对象与方法

### 2.1 分析对象

主要分析材料包括：

- `app-service.js`：应用与页面业务逻辑；
- `app-config.json`：页面注册与窗口配置；
- `_extract/api/`：接口、鉴权、请求中间件及工具模块；
- `_extract/pages/`：页面与首页标签组件；
- `API.md`、`api-endpoints.json`：已整理的接口资料；
- `simulator/`：本次构建的离线行为模型与验证产物。

### 2.2 分析框架

报告采用三层证据口径：

| 层级 | 含义 | 可信度边界 |
|---|---|---|
| 源码事实 | 可直接从反编译代码确认的页面、调用、参数和分支 | 代表当前反编译包中的客户端实现 |
| 模拟验证 | 在内存后端与设备 Mock 中执行并通过检查 | 证明行为模型可运行，不证明服务端一致 |
| 待真机确认 | 原生渲染、权限弹窗、蓝牙信号、H5 页面及服务端规则 | 需要授权环境与真实设备复核 |

### 2.3 安全隔离原则

所有登录、报名、兑换、签到、成绩单和统计请求均由内存后端处理。模拟用户使用虚构身份和伪造 JWT，不读取真实 Storage，不调用生产接口，不发送邮件，不操作真实蓝牙或其他硬件。

## 四、核心业务流程

### 4.1 启动、认证与刷新

应用启动后首先获取远程配置，并检查本地 `tokenv3`。当 JWT 有效期满足客户端要求时，获取当前用户资料；否则进入微信免登流程。微信免登成功后将新 token 写入 Storage，并重新初始化。若微信 openid 未绑定，服务端返回 404，客户端跳转账号密码登录页。

账号密码登录先调用 `wx.login` 获取 code，再提交用户名、密码、code 和验证码字段。出现 419 或 420 时进入验证码 H5，接收答案后重新登录。路由守卫拦截未登录的 `navigateTo` 和 `redirectTo`，但 `reLaunch` 不在其拦截列表中。

应用进入后台时记录时间；再次回到前台且间隔超过一小时，会重新初始化并广播显示事件。检测到小程序更新后，用户确认即可应用更新并重启。

### 4.2 活动列表与报名

活动初始化同时加载活动分类、普通活动、组织和角色。组织活动在切换到对应分类时按需加载。搜索会合并普通活动与组织活动，并按名称过滤；默认排序还结合活动优先级、开始时间、报名窗口和本地计算权重。

报名前，客户端检查：

1. 登录信息与用户角色；
2. 活动受众范围、年级和学院；
3. 报名位与封禁状态；
4. 报名截止时间、活动结束状态；
5. 名额与服务端 digest。

取消报名设置五秒确认倒计时。订阅与取消订阅使用用户学院、年级和角色作为查询参数，并在成功后刷新全局状态。

### 4.3 用户二维码签到

用户开启签到码后，客户端生成基于 base36 的 trace，并请求签到码载荷。载荷经本地编码生成动态二维码，同时进行两类周期操作：

- 每两秒查询该 trace 是否已被扫描；
- 每十秒获取一次新载荷，显示层按更高频率刷新二维码内容。

检测到 `Success` 后，客户端显示成功状态、记录统计并振动。关闭签到码时清除 trace 并关闭屏幕常亮。截屏事件会将签到码设为红色，并在本地记录 24 小时有效的时间戳；该表现本身不等于服务端防伪校验。

### 4.4 管理员签到与扫码

管理员页面按签到或签退类型获取动态码，并周期获取新增签到记录。源码表现为每五秒刷新列表、每四轮更新签到载荷，同时每秒刷新二维码时间参数。截屏时弹出动态码可能过期的提示。

扫码流程先解出管理员码中的活动、操作类型、摘要等信息，再获取当前用户签到载荷，最后调用被动签到接口。请求正文携带被扫描码内容，`X-Token` 携带当前用户载荷的标准 Base64 JSON。

### 4.5 BLE 蓝牙签到

BLE 流程包括权限检查、打开适配器、扫描服务 `2B45`、监听广播和停止清理。仅处理设备名为 `2NDC` 且状态位有效的广播包。

发现多个活动时，客户端按信号强度排序，并结合用户可参与资格筛选；存在多个有效活动时提供选择。单一活动场景选择信号较强的设备。签到前仍需获取用户载荷，再调用 BLE 签到接口。

### 4.6 通知、商城与成绩单

通知模块并行加载栏目树和首页预览，将栏目树、扁平栏目及类型对应 ID 写入本地缓存。搜索支持关键词、新闻类型、栏目和时间范围，并维护最多约十条历史记录。

商城同时加载在售与售罄商品，再按通用商品或用户所属学院过滤。兑换前检查商品状态、库存、限购、封禁和积分类型。无限制积分类型优先使用学院积分，不足部分使用校级积分；模拟器按同一规则更新内存积分与订单。

成绩单页面生成学期选项并读取用户邮箱。提交时发送邮箱、学期数组和类型数组；任务记录按等待、执行、完成、失败四类合并排序。离线模拟只创建等待任务，不发送邮件。

## 七、关键算法与数据格式

### 7.1 动态签到二维码

二维码使用固定时间基准 `1630425600`，将签发时间、有效时长、用户 ID、活动 ID、操作类型、能力位、digest 和 trace 编码为二进制，再经过字节旋转、Base64URL 和字符串旋转。首字符记录旋转档位，解码后恢复原始字段。

模拟器已对多个旋转档位执行编码—解码往返测试，并覆盖 `act_id = -1` 的用户码情况。

### 7.2 BLE 数据包

有效广播为 16 字节、32 个十六进制字符，包含设备标识、状态位、操作类型、能力位、活动 ID、TOTP 和时间戳。解析器检查长度、状态位和保留字段，不符合条件时返回空结果。

### 7.3 商品核销码

核销码使用去除易混淆字符的 32 字符表，将数字订单码转换为自定义进制字符串，并左补齐至六位。订单二维码同时携带订单码、用户 ID 和订单 ID。

## 八、远程配置与隐藏行为

远程配置可控制首页公告、功能入口、轮播和退出登录可用性。关于页依次点击三个指定区域后，可打开隐藏菜单：

- 恢复默认环境；
- 切换测试环境或输入自定义 Base URL；
- 进入 Egg 调试页面。

环境切换后会清空当前用户状态并重新初始化。该能力对测试有价值，但生产版本中应评估是否需要保留，以免普通用户误入不受信任环境。

## 九、安全与实现观察

### 9.1 凭据与数据边界

JWT 保存在本地 Storage，并通过 URL hash 传入资讯、通用 H5 和管理后台。URL hash 通常不随 HTTP 请求发送，但页面脚本可以读取，因此第三方 H5 的脚本可信度、页面跳转和调试日志都属于凭据保护边界。建议仅在必要页面传递最小化数据，并避免在日志中输出完整 URL。

### 9.2 访问统计

客户端具有自建 Umami 统计调用，涉及标签浏览、报名、签到和成绩单等行为。评估隐私合规时，应结合实际 payload、用户告知和数据保留策略判断；本次未对生产统计数据进行读取或外发。

### 9.3 值得复核的实现细节

| 位置 | 观察 | 建议 |
|---|---|---|
| `interceptor.js` | 验证码白名单项缺少前导 `/`，可能与实际路由不一致 | 在真机验证未登录访问验证码页的分支 |
| `pages/common/link.js` | 导航标题设置条件疑似写反 | 检查标题为空与非空时的表现 |
| `pages/new-news/info.js` | 个别缓存回退调用疑似缺少 Storage key | 覆盖无缓存首次进入场景 |
| 签到截屏处理 | 变红和提示主要是客户端表现 | 不应将其当作唯一防伪措施 |
| 两个占位页面 | 导出名单与本地商品核销页没有实际控件 | 文档和测试不要误认为功能已完成 |

以上为代码复核线索，而非已确认的生产故障。

## 十一、限制与后续建议

当前结果不能替代以下验证：

1. 真实服务端的鉴权、digest、名额、封禁和错误码规则；
2. 微信开发者工具及不同手机上的渲染、权限和生命周期差异；
3. 真实蓝牙基站、多活动信号强度和弱网环境；
4. 第三方 H5 的免登、管理、核销及验证码内部逻辑；
5. 生产环境中的隐私告知、日志、数据保留和访问控制。

建议后续在明确授权的测试环境中，以本报告的页面行为矩阵为测试目录，将模拟请求与真实抓包逐项对照，并把服务端响应样例脱敏后补充为回归夹具。对于签到、兑换和管理员操作，应优先验证服务端授权与防重放，而不是仅依赖客户端限制。

## 十二、结论

该小程序不是单一活动展示工具，而是集活动组织、现场签到、资讯、积分激励和成绩输出于一体的综合业务客户端。其核心复杂度集中在全局初始化、动态签到、H5 免登和多角色管理。离线模拟已将这些主要行为整理为可重复执行的模型，可用于代码审查、流程演示和后续授权测试的基线。
